# chart_notes

全世代の曲について、SP・DPの譜面ごとのノーツ数を出力する。
textageの難易度を全曲リストへ転写するとき、曲と譜面が合っているかをノーツ数で確かめるために使う。

```sh
deno run --allow-read=. packages/utils/chart_notes/main.ts \
  [--generation pb]
```

- 原盤は`config/discs.json`の対応で`resources/`から選び、実行ファイルと譜面を読む
- 譜面は復号とLZ展開をしてメモリー上に作る
- `--generation`を付けると、その世代だけを出す

## 出力

標準出力へ、1行目が列名のTSVを出す。

- `generation`は世代である
- `title`は全曲リストの`title`列と同じ形のキーで、管理名が重複する曲は`:{song_id}`を付ける
- `sb` `sn` `sh` `sa` `sl`はSPのBEGINNER・NORMAL・HYPER・ANOTHER・BLACKのノーツ数である
- `db` `dn` `dh` `da` `dl`はDPの同じ順のノーツ数である

数え方は次のとおり。

- ノーツ数はcmd 0とcmd 1のイベントのうち、`c2`が0のものの数である
- DPは1Pと2Pの合計である
- 譜面が無い難易度は空にする
- 平文譜面が無いスロットは空にして、標準エラーへ`<世代> song<曲DB index> slot<n>`の形で報告する

## 譜面の引き方

曲DBの譜面の値(`u32`)から、平文譜面の番号を引く。形は世代で3通りある。

- 3rd〜6thは、値がELFの仮想アドレスである。
  - 番号は、曲順・スロット順に譜面のあるスロットへ付けた連番である。
  - 連番の先頭は、譜面のファイルの最小の番号である。
- 7thと8thは、値の上位4ビットが`0xF`である。
  - 番号は、下位28ビットにファイル表の2番目のアーカイブの件数を足したものである。
- 9th以降は、値がそのままファイル番号になる。

共通の規則は次のとおり。

- 値が`0`か`0xffffffff`のスロットは譜面が無い。
- `us`は譜面スロットの並びが違い、NORMAL・HYPER・ANOTHER・BEGINNERの順でSPとDPが交互になる。
  - この順は、5thにも収録された曲で、各スロットのノーツ数を5thの各難易度と照らし合わせて決めた。

## 確度

- `djt`・`emp`・`pb`は、数えた値が曲DBの`+0x108`のノーツ数と2154譜面で一致した(`PB実測`)。- `7th`・`8th`・`us`は、譜面があるすべてのスロットで平文譜面を引けた。
- 3rd〜6thの連番は推定で、次の2点で裏付けた。
  - 譜面があるすべてのスロットを連番で引くと、5thの最後の曲(曲DB index 141)を除いて平文譜面が見つかる。
  - ノーツ数の大小が`BEGINNER ≦ NORMAL ≦ HYPER ≦ ANOTHER`となる譜面の組が、全世代で98%以上である。
